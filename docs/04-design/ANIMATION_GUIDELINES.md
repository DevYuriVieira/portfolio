 # Animation Guidelines

## Purpose

Motion is used to improve user experience, not to distract.

Every animation must have a reason.

---

# Motion With Purpose

Animations should communicate:

- hierarchy;
- interaction;
- transition;
- feedback.

Avoid animations that exist only for visual decoration.

---

# Performance First

Animations must prioritize:

- smooth rendering;
- low CPU usage;
- minimal layout changes.

Prefer animating:

- transform;
- opacity.

Avoid unnecessary:

- expensive filters;
- continuous calculations;
- heavy effects.

---

# Accessibility

All motion must respect:

prefers-reduced-motion


Users who disable animations should receive an equivalent experience.

---

# Consistency

Motion must use centralized tokens.

Examples:

- duration;
- easing;
- transition patterns.

Avoid random timing values.

---

# Future Advanced Motion

Future technologies may include:

- GSAP;
- WebGL;
- Three.js.

However, they must only be introduced when they provide real value.

Technology should support the experience, not become the experience.

---

# Avoid Excess

The project does not aim to maximize animations.

The goal is:

minimal,
intentional,
premium interaction.
