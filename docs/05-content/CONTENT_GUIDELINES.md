 # Content Guidelines

## Purpose

This document defines standards for all portfolio content.

The portfolio should communicate professional identity, technical ability and problem-solving mindset.

---

# Languages

Primary language:

pt-BR

Secondary language:

en


All important content should support internationalization.

---

# Writing Style

Content should be:

- professional;
- human;
- direct;
- authentic.

Avoid generic statements.

Bad:

"Passionate developer creating amazing solutions."

Good:

"Developed scalable applications using Angular, Spring Boot and modern software practices."

---

# Project Storytelling

Projects should explain:

## Context

What problem existed?

## Solution

What was built?

## Technology

Which tools were used?

## Decisions

Why were specific approaches chosen?

## Impact

What value was created?

---

# Avoid AI Generated Tone

Content must avoid:

- exaggerated adjectives;
- empty marketing phrases;
- unnecessary buzzwords.

The objective is credibility.

---

# Professional Identity

The portfolio should demonstrate:

- engineering maturity;
- technical decisions;
- continuous improvement;
- attention to quality.
